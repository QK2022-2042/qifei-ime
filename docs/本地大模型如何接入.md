# 本地大模型如何接入

> 这一版的默认路径是 **直连 llama.cpp**：自己下载的 `.gguf` 选进来就能用。
> **不用装 Ollama，不用下载 `llama-server.exe`，不用联网，也不会往 Ollama 里复制一份模型。**
> 设置都在 **设置中心 → 大模型**。

---

## 一、三种后端

| 后端 | 适合谁 | 要不要装东西 | 联网 |
|------|--------|--------------|------|
| **直连 llama.cpp（默认 / 推荐）** | 所有人 | **什么都不用装**，程序自带动态库 | 不联网 |
| 远程 API | 用 DeepSeek / Moonshot / 智谱 | 无 | 要联网 |
| 本机 Ollama（可选） | 本来就装了 Ollama 的人 | 装 Ollama | 不联网 |

打开 **设置中心 → 大模型**，在「后端」里选。老配置如果还停在 Ollama，
第一次打开设置页会自动切到「直连 llama.cpp」（只迁移一次，之后手动选回 Ollama 不会被改掉）。

---

## 二、开箱即用 / 换成自己下载的模型

**开箱即用（默认）**

安装包已经**内置** `Qwen2.5-1.5B-Instruct Q4_K_M`（约 1.04GB，带官方 chat template）。
第一次装完它就落在 `models/llm/qwen2.5-1.5b-instruct-q4_k_m.gguf`，并被 **自动识别设为默认模型**：
打开 **设置中心 → 大模型**，能看到 `llama.cpp 就绪` 和这个文件名，润色角色直接可用。
听写客户端启动时会在后台预热，不用手选、不用注册、不用联网。

> 首次启动引导要下载的约 414MB 是**语音识别模型**（SenseVoice），跟润色大模型是两回事，别搞混。

| 场景 | 怎么做 |
|--------------|--------------|
| 全新安装 | 什么都不用做，模型已在 `models/llm/` |
| 覆盖安装 / 升级 | 你人工换过的模型原样保留，安装包不会覆盖 `models/` 下已存在的文件 |
| 想升级或换个模型 | 设置中心 →「大模型」→ **选择模型文件**，或把新 `.gguf` 拷进 `models/llm/` |
| 想重新下载 / 恢复内置模型 | 设置中心 →「大模型」→ **下载推荐润色模型**，人工确认后覆盖重下（约 1.04GB，唯一需要联网的动作，默认选「否」） |
| 想下载其他大模型 | 自己把 `.gguf` 拷进 `models/llm/`，或用「选择模型文件」/「添加扫描目录」；程序不会自动下载 |
| 完全不能联网、要批量分发 | 把 `启飞输入法-LLM润色模型包.zip` 解压到程序目录，文件自动落到 `models/llm/` |

命令行等价操作（多源、断点续传、带校验）：

```
python tools/download_llm_model.py            # 已有有效模型则跳过，否则下载 / 续传
python tools/download_llm_model.py --check   # 只校验已内置的模型
python tools/download_llm_model.py --force   # 人工确认后覆盖重下
```

独立补包在有模型的机器上生成一次即可（新安装包已自带模型，它现在主要用于给旧版补模型或离线换模型）：

```
python tools/make_llm_model_pack.py           # 生成到 dist/ 并校验 CRC
python tools/make_llm_model_pack.py --check  # 只校验已有补包
```

补包里只有一个 `models/llm/qwen2.5-1.5b-instruct-q4_k_m.gguf`，
用 ZIP_STORED（GGUF 已经量化过，再压缩省不了多少，但打包和解压都快）。
解压到程序目录后不用重启、不用注册，界面刷新一下就会自动选中。

下载器会核对文件大小、`GGUF` 魔数、元数据，还要确认带 `tokenizer.chat_template`；
下载中的文件先写 `.part`，校验通过才改名，半截文件不会被当成模型。
下载按钮只在你主动重下 / 补模型时才联网（内置模型已就绪时会先确认，默认「否」），之后推理全程离线。

**为什么现在把模型打进包**：以前主包不带模型，第一次装完还得手动补 1GB 才能用润色，
门槛太高。现在安装包自带一份推荐模型，装完即可用；**换模型完全由你手动决定**，
程序不会自动下载，覆盖安装也不会替换你已有的模型文件。代价是安装包从约 165MB
变成约 1.2GB。需要小包时构建时设 `QIFEI_BUNDLE_MODEL=0` 就回到旧策略。

**只带这一个**：`models/` 下可能还有 ASR 权重和下载缓存，
`installer/build_installer.py` 用白名单只放行内置模型这一个条目，
避免把几个 GB 的语音模型误打进包；模型用 `ZIP_STORED` 存，GGUF 已量化，
再压缩省不了多少却要白等几分钟。

**人工升级 / 换成自己下载的模型**

1. 下载一个 `.gguf` 文件（HuggingFace / ModelScope 上都有，**要选带 `-Instruct` 的对话模型**）；
2. 后端保持 **直连 llama.cpp（推荐）**，点 **选择模型文件** 选中它；
3. 点 **测试连接**，看到「连接正常 · 首字 x.xs」就能用了。

导入时程序会读 GGUF 文件头，把参数量、量化方式、上下文长度、体积显示出来，
并检查有没有 chat template：ASR / 语音识别 / 纯补全模型会在下拉里标成「（非对话模型）」，
选中后明确提示，自动选中时也会跳过。**模型文件不用挪位置、不用注册、不用复制**，
选中后由进程内的 llama.cpp 直接加载。

模型下拉还会自动扫描这些目录：程序目录的 `models/llm`、`%USERPROFILE%\Downloads`、
`%USERPROFILE%\Models`、LM Studio / Ollama 的模型目录。
放不下的地方可以点 **添加扫描目录** 指定。

## 三、它是怎么做到的（不装 Ollama 的原理）

项目里本来就带着 llama.cpp 编译好的动态库：

```
core/server/engines/llama/bin/
    llama.dll  ggml.dll  ggml-base.dll
    ggml-cpu-*.dll  ggml-vulkan.dll  libomp140.x86_64.dll ...
```

流程是：

```
.gguf 文件
  → llama_model_load_from_file / llama_init_from_model   （ctypes，进程内）
  → llama_chat_apply_template → tokenize → decode → sampler
  → 内嵌的 127.0.0.1:11500 OpenAI 兼容接口（标准库 http.server，SSE 流式）
  → llmkit 的 HTTP 客户端 / 听写客户端
```

也就是说：

- **没有 Ollama 服务**，不会去查 `11434`，不会调 `ollama create`，不会 `ollama pull`；
- **没有额外 exe**，不需要 `llama-server.exe`；
- 内嵌服务只监听 `127.0.0.1`，不走系统代理，纯本机；
- 上层仍然走 OpenAI 兼容接口，所以流式输出、分级超时、冷启动重试、预热这些
  已经验证过的逻辑全部复用，「测试连接通过 = 实际听写能用」。

如果动态库换了位置，或想用自己的一份，可以设置环境变量 `QIFEI_LLAMA_DLL_DIR` 指向 DLL 所在目录。
界面上「llama.cpp 就绪 / 动态库缺失」的状态标签就是查这个。

不用准备真实模型也能验证这套动态库是否可用，在仓库根目录跑：

```
python tests/test_llm_kit.py
```

自检会验证 DLL 加载、C API 是否齐全、ggml 后端真的注册上了、按值传递的结构体
布局（ABI）、chat template 格式化、打包后的 DLL 定位，以及「内嵌服务 → SSE →
运行时对话」全链路。以后换了 llama.cpp 版本，跑一次就能先排除结构体错位这类问题。

把 `.gguf` 放进 `models/llm/` 后，还可以跑**真实模型**的端到端验证
（加载 → 生成 → SSE → 运行时对话）；没有模型时它会自动跳过，不会拖慢常规自检：

```
python tests/test_llm_real_model.py
python tests/test_llm_real_model.py "models/llm/qwen2.5-1.5b-instruct-q4_k_m.gguf"
```

推荐润色模型的本机实测（纯 CPU、ctx 2048）：进程内加载 1.4s，直接生成
「我是阿里云开发的一款智能机器人…」，SSE 流式「测试成功。」，
`LLMProcessor` 运行时对话「OK」，最后打印 `REAL_MODEL_RESULT=PASS`。

排查加载问题时可以设 `QIFEI_LLAMA_LOG=1` 保留 llama.cpp 原始日志。

> 如果动态库确实不可用，程序会**明确报错**并允许回落到外部 `llama-server.exe`
> （放到 `runtime/llama/` 下），不会静默降级偷偷连到别的地方。
> 也可以在「推理引擎」里手动选「外部 llama-server.exe」。

## 四、可调的推理参数

「llama.cpp 推理参数」这一栏只对直连后端生效：

| 设置 | 默认 | 说明 |
|------|------|------|
| 推理引擎 | 自动 | 优先进程内动态库；失败才找外部 exe |
| 上下文长度 | 4096 | 越大越吃内存；超过模型训练长度会自动收敛到训练值 |
| GPU 卸载层数 | 0 | 0 = 纯 CPU（最稳）。有独立显卡可填 `99` 全部卸载，明显更快 |

模型本身常驻在客户端进程里，不需要 Ollama 那种 `keep_alive` 设置。
在设置页点「测试连接」时会临时在界面进程里加载一次，测完立即释放，
**正式听写由客户端独占加载**，避免 GUI 和客户端各加载一份把内存吃满。

## 五、超时为什么以前老是失败

旧版本把所有请求的超时统一写成 **2 秒**。本地模型冷启动光加载权重就要几十秒，
所以只要模型没提前驻留内存，**每一次都必然超时**。

现在的策略：

| 项目 | 默认值 | 说明 |
|------|--------|------|
| 连接超时 | 5 秒 | 连不上就赶紧报错，不干等 |
| 生成超时 | 600 秒 | 从发请求到模型开口的等待上限 |
| 冷启动重试 | 1 次 | 本地模型首次超时后自动再试一次 |
| 模型常驻 | 常驻进程内 | 每次说话不用重新加载 |

两个超时都能在页面上调。机器慢、模型大（14B 以上）就把生成超时再往上加。

另外「开机后自动预热模型」默认开启：听写客户端启动时就把模型读进内存，
第一句话不用等几十秒。内存吃紧的机器可以关掉。

## 六、和 LLM 角色文件的关系

`LLM/` 目录下的角色文件（`default.py`、`翻译.py`、`小助理.py`）仍然决定
**提示词、触发前缀、输出方式**，但连接信息可以被界面接管：

- 页面上「所有角色统一用这个模型」**开启**（默认）：
  所有角色都改用你在页面上选的本地模型，不用挨个改角色文件；
- **关闭**：只有角色文件里 `provider` 本来就是本地类型（`ollama` / `local`）的才会被覆盖，
  用 DeepSeek 之类远程服务的角色保持原样。

想给某个角色单独指定模型，就把这个开关关掉，再改角色文件里的 `provider` 和 `model`。
配置文件里还没有 `llm` 段时，客户端会用和界面一致的默认值（直连 llama.cpp），
不会偷偷退回 Ollama。

## 七、可选：如果你本来就装了 Ollama

在「后端」选 **本机 Ollama（可选）**，再点 **导入到 Ollama**：

- 程序读 GGUF 头，生成一份内容只有 `FROM "<本地绝对路径>"` 的 Modelfile，
  调本机 `ollama create` 注册 —— **整个过程不联网**，也不会 `pull`；
- Ollama 服务没开时会自动 `ollama serve` 拉起来；
- 注册后模型会被复制进 Ollama 自己的存储，原文件删掉也不影响使用。

这只是给已有 Ollama 的用户留的兼容路径，不是必需步骤。

## 八、常见问题

**Q：选择文件后模型下拉里还是找不到？**
点「重新扫描」。还不行就看标签提示——多数是文件不是标准 GGUF
（只下了半截、或者下成了 `.gguf.part`），或文件放在没被扫描到的目录。

**Q：状态显示「动态库缺失」？**
确认程序目录里 `core/server/engines/llama/bin/` 下有 `llama.dll`、
`ggml.dll`、`ggml-base.dll`。也可以设 `QIFEI_LLAMA_DLL_DIR` 指向别的目录，
或在「推理引擎」里改用外部 `llama-server.exe`。

**Q：测试连接提示「模型不可用」？**
先确认「选择模型文件」选中的 `.gguf` 路径还在。直连模式不需要安装任何东西，
也不需要联网下载；报错里会给出具体原因。

**Q：说话后没润色，只有原文上屏？**
看托盘/Toast 的红色提示。常见原因：没选模型文件、模型加载失败（显存/内存不够），
或「启用大模型润色」被关掉了。

**Q：显存不够 / 加载失败？**
换更小的量化（`Q4_K_M` 而不是 `Q8_0`），或换 4B 以下的模型；
把「GPU 卸载层数」调回 0 走纯 CPU；也可以调小「上下文长度」。

**Q：测试连接返回 `language Chinese<asr_text>...` 这种奇怪文本？**
选中的是 ASR（语音识别）专用模型：它没有 chat template，只会按转写格式输出，
不适合润色 / 对话。链路本身是通的，换一个带 chat template 的通用对话模型
（比如 `*-Instruct` 的 GGUF）就能得到正常回答。现在程序会直接在下拉里标
「（非对话模型）」，测试连接也会报「模型类型不对」，不会误报连接正常。

**Q：下拉里有个模型标着「（非对话模型）」，能删吗？**
那是没有 `tokenizer.chat_template` 的模型（常见于 ASR、embedding、纯补全）。
程序不会自动选它，也不会删你的文件。确认用不上就可以直接从磁盘删掉释放空间，
比如之前为实测拷进来的 `models/llm/qwen3_asr_llm.gguf`（1.37GB）。
删完点「重新扫描」即可。

**Q：这台电脑完全不能联网，怎么装润色模型？**
在能联网的机器上跑 `python tools/download_llm_model.py`（或手动下载
`qwen2.5-1.5b-instruct-q4_k_m.gguf`），把同名文件拷到程序目录 `models/llm/`。
程序会自动识别并设为默认；之后推理全程离线，不需要下载按钮。

**Q：`models/` 目录下那几个 `Ollama-*.py` 是什么？**
历史遗留的调试脚本，直接 `import ollama`，项目运行时**不会加载**它们
（角色文件只从 `LLM/` 目录读取）。直连 llama.cpp 完全用不到，也不用为它们装 Ollama。

**Q：远程 API 走公司代理连不上？**
程序对 `127.0.0.1` / `localhost` 强制绕过系统代理，本地模型不受影响；
远程 API 目前直连，需要走代理时请配置系统级代理。
